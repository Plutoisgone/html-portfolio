# Mini-SIEM Phase 0.2 — Security assessment

**Decision: NOT ACCEPTED FOR PRODUCTION.** Lab-only source candidate. Review date: 2026-11-24. This is a targeted second-pass remediation of the supplied Phase 0.1 ZIP, not an exhaustive independent penetration test. No zero-vulnerability guarantee is possible. The Phase 0.1 reports are retained as historical records and do not establish current live verification.

## Residual risks and production blockers

- **High: Compromised web application/database credential.** The web role still has privileges to manage users and sessions and append audit rows. A stolen runtime credential can bypass UI authorization and fabricate future audit entries. Separate worker, emergency and owner identities reduce blast radius but do not solve the single web application's trust boundary. A separate authentication/admin service with an independently enforced authorization interface and isolated credentials is needed to reduce this further. Application-written audit events cannot prove the truth of a malicious application's actions.
- **High: Unverified software supply chain.** Exact Python lock installation, CVE scan, dependency compatibility, base image/OS scanning, and digest pinning remain pending. Existing requirements lock retained; no fabricated package versions or CVE result. Image tags are mutable. CI checks are not evidence of a passed run.
- **High: Deployment security unverified.** No actual Docker, PostgreSQL, nftables or Caddy execution here. Verify initialization, roles, TLS, firewall and actual ingress paths on a disposable Hyper-V VM. The host script is intended for a dedicated Ubuntu VM only; review it before running as root. Its actions can affect SSH connectivity.
- **High: Immutable audit validation unverified.** Wasabi live integration, version permissions, Object Lock enforcement and disaster recovery remain release blockers. S3 is optional for lab use only. With S3 disabled the local HMAC checkpoint does not resist restoration of an older signed checkpoint by a privileged host attacker. Remote checks do not defend against compromised worker/HMAC key, bucket control plane, expiration of all retained evidence, or a dishonest endpoint.
- **High: Identity assurance depends on Entra configuration.** Enforce phishing-resistant MFA and single-tenant application assignment; review sign-in/revocation policies. A local session can remain valid until local revocation/expiry even if upstream access changes. Live SSO, logout, token replay and CA enforcement are untested.
- **Medium: Availability and scaling.** Full-chain verification and listing remote versions each cycle scale with data volume; CPU, memory, storage growth, retention and attack resistance not measured. Add incremental authenticated checkpoints and independent alerting before scale. Concurrent export workers are not supported. Direct network floods remain an infrastructure concern.
- **Medium: Failure recovery.** A crash after upload of remote checkpoint but before local save intentionally fails closed; investigate and reconcile authenticated remote and database chain with evidence preserved. No automated recovery tested. Do not reset checkpoint or delete remote evidence to clear an error.
- **Medium: Infrastructure threat model.** Hyper-V administrators, host root, Docker daemon, database bootstrap, Entra administrators and worker credentials are trusted to varying degrees. Root-owned source/config directories and secured backups are required. Host disk encryption and physical security are external. Current ClickHouse profile is not approved for use.
- **Scope:** no collection engine, agents, vendor integration, detection/correlation, or enforced tenant isolation exists yet. No production multi-tenancy. Phase 0.2 cannot be compared as a complete SIEM to Wazuh.

## Acceptance

See `TEST_RESULTS.md` and `DEPLOYMENT_GUIDE.md`. All unresolved high risks must be remediated or explicitly accepted by the system owner through a documented security risk process (not a claim that the system is vulnerability-free). Production remains blocked until live testing, dependency/image scans and independent review pass.
